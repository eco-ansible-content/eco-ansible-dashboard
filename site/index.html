How to read these results

Actions: summarizes GitHub Actions for the latest commit on each repository’s default branch, using the newest run of each monitored workflow. All active workflows are monitored unless specific workflows are selected. External CI and PR-specific checks are not included.

Actions statuses
StatusMeaning
PassingEvery monitored workflow completed successfully on the current commit.
FailingAt least one workflow failed, timed out, failed to start, or requires action.
RunningAt least one workflow is running, queued, or waiting, with no known failure.
UnknownA workflow has no run for the current commit, was cancelled or skipped, or returned a neutral or unrecognized result. A configured workflow that cannot be found also produces this status.
No ActionsThere are no active workflows being monitored.
Data errorSome repository data could not be collected. This can include other metrics, such as issues or pull requests, even when workflow results are available.

When results differ, the priority is Failing → Running → Unknown → Passing. A collection error overrides the result with Data error. “Actions need attention” counts repositories marked Failing, Unknown, or Data error.

Unknown does not necessarily mean something is broken. A release workflow that runs only for tags may have no run on the latest default-branch commit. Open repository details to inspect individual workflows and their GitHub links.

Core: supported versions come from meta/runtime.yml. CI tested versions are configured coverage from public CI definitions, including Azure Pipelines and reusable workflows; they do not imply a successful run. Open repository details for source links.

Issues: New issues counts open issues created in the past seven days. Total open issues counts all currently open issues, regardless of when they were created. Both counts exclude pull requests. Needs triage means a needs-triage label, or no assignee/comments and no triaged label. This is a configurable signal of likely pending work, not proof that nobody has read the issue.

Update schedule: fresh data collection is scheduled every 30 minutes, at 7 and 37 minutes past each hour (UTC). Collection also runs after pushes to this dashboard’s main branch, or manually through Actions → Dashboard → Run workflow in the dashboard repository. Changes in monitored repositories appear after the next successful collection and deployment. GitHub can delay or drop scheduled runs, so this interval is an intended cadence rather than a guaranteed refresh.

Viewing the latest data: an open tab does not automatically fetch new snapshots. Use Reload data or refresh the page to load the latest published snapshot; neither action starts a new collection. Reload data confirms whether a newer snapshot was available. “Updated … ago” shows the age of the snapshot you are viewing. A warning appears when it is over 90 minutes old.
